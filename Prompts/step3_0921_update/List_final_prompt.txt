Your task is to merge List A and List B into one unified list, while leveraging the full conversation context — especially to accurately detect Thai National IDs and embed detection findings directly into the merged context.

> 🔄 Critical Flow Reminder:
> 1. Match entries → 2. Detect Thai ID using full conversation → 3. Write merged context (including ID findings) → 4. Set to_drop → 5. Finalize & sort.

### ✅ Step 1: Understand the Goal

1. Includes all information from both List A and List B (union).

4. Detect Thai National IDs using the full conversation — embed findings in context.
5. Flag confirmed Credit/Payment card entries (using tag information) → set "to_drop": false. All others → "to_drop": true.

### ✅ Step 2: Match Entries by Time and Speaker — STRICT 1:1 MERGE

To determine if two entries (one from A, one from B) refer to the same event:
- Compare their start, end, and speaker.
- If all three are within 0.01 seconds (for times) and the speaker matches → they represent the same segment.
- Use this as the primary key: (round(start, 2), round(end, 2), speaker)

> 🔍 Example:
> A: start=1050.37, end=1052.11, speaker="Caller"
> B: start=1050.37, end=1052.11, speaker="Caller" → ✅ Same event

> ⚠️ CRITICAL: Only merge if BOTH start AND end timestamps match within 0.01s. Do NOT merge entries that are adjacent or overlapping but not identical in time boundaries. Each merge must be 1:1 — one A with one B — never merge multiple A’s with multiple B’s into one long entry.

### ✅ Step 3: For Each Matched Pair — Detect Thai ID BEFORE Writing Context

⚠️ Thai ID detection must happen BEFORE you write the merged context — so findings can be embedded.

#### A. Gather Raw Materials
- Collect both context strings from A and B.
- Note all tags from both.
- Note the time window: start = min(A.start, B.start), end = max(A.end, B.end)

#### B. Thai National ID Detection — Conversation-Aware & SEMANTICALLY ROBUST

Scan both raw contexts AND the full <conversation> transcript for Thai ID indicators — prioritize semantic intent over literal keywords.

✅ Positive indicators (ANY of these present = likely Thai ID):
- Contains keywords:
"ID", "citizen ID", "เลขบัตรประชาชน", "national ID", "identification", "13 หลัก", "ID card number", "ID number", "ID card"
- Contains a 12–13 digit number (allow ±1 digit for transcription error)
- That number starts with 1, 2, 3, 4, 5, 6, 7, or 8
- That number does NOT start with 0 or 9

🔶 CRITICAL SEMANTIC OVERRIDE RULE (UPDATED & CLARIFIED):

> 🚨 ALWAYS CHECK IF THE CALLER OR AGENT EXPLICITLY ASKED FOR A “13-DIGIT NUMBER” OR REFERENCED “13 หลัก” — THIS IS THE STRONGEST SIGNAL FOR THAI ID.

→ If the conversation explicitly requests or refers to:
- “เลขบัตรประชาชน”
- “บัตรประชาชน”
- “13 หลัก”
- “บัตรที่มี 13 หลัก”
- “หมายเลขบัตร 13 หลัก”
- Or mentions “missing 1 digit” when 12 digits are provided → e.g.,
[Agent]: “ที่คุณแจ้งมามีแค่สิบสองหลักครับ ขาดไปหนึ่งหลัก”
→ This implies the expected number is 13 digits, hence Thai National ID.

→ Then: ANY number provided in that context is a Thai National ID — EVEN IF the speaker calls it “card number”, “หมายเลขบัตร”, or stumbles while speaking.

→ Conversely, if the conversation explicitly refers to:
- “credit card”, “debit card”, “member card”, “PAN”, “account number”, “16 หลัก”, “4 หลักสุดท้าย”, “first 4 digits”
→ Then it is NOT a Thai ID, even if format matches.

🔶 SPECIAL CASE: SPLIT NUMBERS DUE TO SPEECH DISFLUENCIES

> 📌 If a number is split across utterances (e.g., due to “uh”, “wait”, “ok”, pauses, or hesitation) — such as:
> - “4 digits... uh... 12-13 digits” → likely first 4 + next 12 = 16-digit credit card
> - “12-13 digits... wait... 4 digits” → likely first 12 + last 4 = 16-digit credit card
>
> → ❌ DO NOT classify as Thai ID.
> → ✅ Only classify as Thai ID if:
> - The full 12–13 digit sequence stands alone (not part of a longer sequence), AND
> - The context explicitly asks for 13 digits or Thai ID, OR
> - The agent confirms it’s 13 digits / points out a missing digit from 13.

> 💡 Example 1 — Split credit card:
> Caller: “My card is... uh... 4817... then 20010203040506” → total 16 digits → ❌ Not Thai ID.
>
> 💡 Example 2 — Thai ID despite “card” wording:
> Agent: “รบกวนแจ้งเลขบัตรประชาชน 13 หลักครับ”
> Caller: “Card number... uh... 1207140145732” → ✅ This is Thai ID — context overrides terminology.
>
> 💡 Example 3 — Agent confirms missing digit:
> Caller: “120714014573”
> Agent: “คุณลูกค้าครับ ขึ้นต้นด้วย 1 แล้วมีแค่ 12 หลัก รบกวนเช็คให้ครบ 13 หลักด้วยครับ” → ✅ Confirmed Thai ID — agent is expecting 13 digits.

→ If ambiguous, default to semantic context over terminology or isolated number format.

→ Record your findings. You will embed them in the context next.

#### C. Write Merged Context (Include Detection Findings)

- ✅ Thai ID confirmed via agent’s “missing digit” prompt:
"Caller provides 12-digit number; agent responds requesting missing 13th digit — confirms context is Thai National ID. Final number: 1207140145732."
